# 额外平台手续费设计

状态：待用户确认；仅完成只读调查，未实现、部署或发送交易。

## 已确认的需求

- 在原市场手续费之外，额外收取 **0.5%（50 bps）** 平台手续费，由卖方承担。
- 买方平台费为 **0**；买方不增加平台费授权、开通、预存或付款步骤。
- 平台费以 BSC USDT 支付，收款地址为 `0x3D91889209f9ca69b7Cb73D7a8C463f4deFB5c15`，地址格式和校验和均已验证。
- 不修改原市场的管理员、手续费或收款人。

## 当前系统与证据

- BSC 主网（chain ID 56），原市场 `0xfaD7D1300e43A7b8F0b5a2FE5eF9A306f89c6EfC`，USDT `0x55d398326f99059fF775485246999027B3197955`。
- 当前网页直接授权原市场并调用 `fill(id, tokenIds)`；买单仍由买方钱包直接调用 `placeBid` / `cancelBid`。
- 2026-10-24 只读查询：全局 `feeBps()` 为 100；`setFee(uint16,address)` 的只读模拟对 owner 成功、对普通地址以 `OwnableUnauthorizedAccount` 拒绝。新增平台费不依赖该管理权限。
- `bid(uint256)` 返回六个 ABI word。区块 129389993 对 8241、8210、8216、8223、8214 等真实订单读取，与索引中的买方、资产、价格、数量、100 bps 费率、时间戳一致。此观察是候选 ABI 依据，仍须在分叉测试中确认完整类型与成交语义；已成交订单的查询可能全部为零。
- 当前索引会把 `BidFilled.seller` 直接显示为卖方，路由成交后需补充真实卖方关联，避免把平台合约显示为卖家。
- 原合约未获得已验证源码；本次没有做真实 router 分叉测试，不能把通用 ERC-721 标准视为当前合约兼容性证明。

## 方案比较

1. **推荐：新增仅卖出成交的收费结算合约。** 保留原市场买单与买方身份；卖方改为经新合约卖出，在同一笔交易内完成 NFT 中转、原市场成交、平台费与卖方净额支付。具体兼容性必须先验证。
2. 独立收取一笔 USDT 转账再成交：收费与成交难以保持原子性，可能只收费却未成交，不采用。
3. 自建完整市场：可自行制定全部费率，但会有独立买单簿和资金迁移，超出当前额外收费需求，不采用。

这笔平台费仅对通过新结算合约完成的交易生效。直接调用原市场或使用其他网站的交易不会自动给本平台付费。

现有旧买单无需买方开通平台费即可被新卖出路径使用，因为本方案不向买方扣款。原市场直接成交仍按原规则结算且无额外平台费；不引入双边收费或买方授权状态判断。

## 建议的结算规则

以下是实现方建议，需与本设计一并确认：

- 计费基数为订单**成交总额**，不是扣除原市场费后的金额。
- 以 USDT 最小单位做整数计算：`platformFee = floor(gross * 50 / 10000)`；按实际订单自带费率计算原市场费，不能直接假定所有历史订单都使用全局最新费率。
- 示例：成交 100 USDT、原市场费率 1% 时，原市场收 1 USDT、平台收 0.5 USDT、卖方收 98.5 USDT。Gas 另以 BNB 支付。
- 第一版只支持当前网页的单个 NFT 成交，RELICS / LOOMS 均纳入验证。
- 第一版平台费率 50 bps、上述收款地址、原市场与资产地址在部署后固定，不增加管理员随时调税或改收款地址的入口。未来变更需另行设计和部署。

## 交易与授权

1. 前端刷新链上订单和报价，展示原市场费、平台费、卖方净额、收款地址及新增授权对象。
2. 卖方仅授权本次指定 NFT 给收费结算合约；不要求无限 USDT 授权或全系列 NFT 授权。已有给原市场的 NFT 授权不等于给新合约的授权。
3. 卖方自己签名调用新的卖出入口。合约校验真实订单、资产、卖方、数量、最低到账金额和交易期限；保留原市场的自成交限制，不能因 router 改变调用者而绕过。
4. 候选执行路径：从卖方接收指定 NFT，逐个授权原市场并调用 `fill`，用本次成交的 USDT 余额增量结算。任何 NFT 接收限制、caller 限制或付款语义不兼容，先停止接入并报告，不改用两笔收费绕过验证。
5. 新合约将平台费直接转到指定钱包，余款直接转给卖方；正常结束不留用户 NFT 或本次 USDT，不能把合约原有余额当作本次收益。
6. NFT 或任一 USDT 支付失败，全部业务状态回滚，避免只收平台费却未成交；已消耗的链上 Gas 不退还。

合约需限制可调用市场和资产，采用重入保护、可靠的 ERC-20 返回值处理、订单与收款校验，并保护 NFT 回调路径。前端提交最低净到账与截止时间，避免报价过期后静默少到账。

## 前端与索引

- 买入、挂单、撤单仍直接走原市场，避免 router 成为订单里的买家或退款接收人。
- 卖出区显示原市场费、平台费 0.5%、合计费率与净到账；全部金额使用 bigint / USDT 最小单位计算。
- 每次签名前验证 chain ID、新合约代码与固定配置一致，刷新订单、NFT owner 和授权；RPC 错误不能默认显示为零费用。
- 新合约发出可关联原市场 fill 的事件，包含真实卖方、订单、NFT、成交总额、原市场费、平台费、卖方净额。
- 索引在同一交易的日志范围内关联两种事件，仅对确认为该 router 的成交补充真实卖方与平台费，不重复计算成交量或 K 线。缓存版本/指纹须纳入 router 身份，升级时安全回放或迁移。
- 保留两秒轮询、singleflight 和历史节点分池；router 事件并入已有日志区间请求，不新增逐笔历史 RPC 轮询。

## 上线前必须验证

- 原市场 getter 的 ABI、每单费率、NFT/USDT 接收人、caller 限制与撤单/耗尽语义。
- 两种 NFT 在固定 BSC 分叉区块下完整走通：单 NFT 授权、路由中转、原市场 fill、三方余额变化、最终 NFT 买方所有权。
- 0.5% 的整数边界、最低到账、过期、订单被抢先成交/撤销、不属于卖方的 NFT、重复调用、错误资产与重入等失败场景。
- 任一步失败时，NFT 所有权、买单剩余数量和 USDT 余额全部回滚；失败测试不能只检查 UI 提示。
- 索引显示真实买卖方、一次成交量，以及两种手续费；现有买单/撤单、图表、RPC 和三个页面回归通过。

## 交付与链上操作边界

先交付合约源码、测试、部署脚本和前端接入代码。合约部署与用户交易由用户控制的钱包签名；不代用户签名、授权或支付 Gas。

收费结算合约未完成测试、部署及链上配置核验前，不发布“平台费已生效”的页面或扣款流程。现有网站不会仅因写入该设计就开始收费。
